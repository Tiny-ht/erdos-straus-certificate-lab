# Agent 工作流与验收合约

本项目首先提供有限整数搜索、证书核验及其数学边界。下面是可以在这些接口上扩展的 agent 研究工作流。LLM 接入、自动文献维护、长期任务调度与持续运行服务属于后续工作，不能把这份设计视为它们已经部署的证据。

## 1. 搜索可以复杂，验收必须明确

候选产生者可以尝试不同的公式、分支顺序与启发式策略。检查器只接受精确证书，并重新计算决定结论的条件。

对调度器而言，三个基本结果是：

| 结果 | 含义 | 调度动作 |
|---|---|---|
| 正见证 | 某个具体输入有一个已检查的解 | 完成这个输入的存在性任务 |
| 分支排除证书 | 指定作用域内没有解 | 仅关闭该分支 |
| `UNKNOWN` | 当前尝试未完成 | 保留任务，调整预算或方法 |

证书不应只携带一段解释。它应包含输入、分支标识、语义版本、证明理由以及检查器所需的整数数据。相同的数据不能被重放到另一个输入或分支。

## 2. 八种逻辑职责

这些角色可以由少量并发 worker 轮换承担，不要求八个独立常驻进程。

| 角色 | 工作 | 可验收产物 |
|---|---|---|
| 文献核验 | 阅读原始论文并记录适用条件 | 来源、定理号、假设和版本 |
| 目标与归约 | 固定命题和完整量词 | 引理合约与依赖图 |
| 数学研究 | 寻找参数恒等式与整除结构 | 精确的候选命题和推导 |
| 构造与计算 | 枚举实例、搜索参数、生成证书 | 整数或有理数对象 |
| 反例与障碍 | 攻击候选规则和错误剪枝 | 具体反例或完整分支排除 |
| 形式化证明 | 将稳定引理转为形式化证明 | 可重放证明及依赖信息 |
| 独立审稿 | 从声明和前提出发重建论证 | 验收结果或明确缺口 |
| 调度与记忆 | 分配预算、记录失败与合并结果 | 任务状态与下一步选择 |

提出证明与最终验收应分离。多个 agent 的一致意见不能把猜测升级成定理。

## 3. 模板反例的量词

一个固定版本的公式模板 $T_\theta$，若声称

$$
\forall n,\quad D_\theta(n)\Longrightarrow W_n(T_\theta(n)),
$$

则攻击者需要提供

$$
D_\theta(n_0)\land\neg W_{n_0}(T_\theta(n_0)).
$$

这只反驳该模板，不反驳输入 $n_0$ 的全部解。

例如，公式

$$
x=(n+1)/4,\qquad y=z=n(n+1)/2
$$

在 $n\equiv3\pmod4$ 时产生正整数解。如果把声明域改成所有奇数，$n=5$ 就以分母不为整数的方式反驳新版本。但 $5$ 不在原声明域内，因此不能用它反驳原规则。

### 带自由参数的模板族

如果声明是

$$
\forall n\in D,\quad\exists\theta\in\Theta,\quad W_n(T_\theta(n)),
$$

那么一个 $(n_0,\theta_0)$ 失败只能排除这个参数选择。要打掉模板族对 $n_0$ 的覆盖，需要证明

$$
\forall\theta\in\Theta,\quad\neg W_{n_0}(T_\theta(n_0)).
$$

无穷参数域不能用“有限次尝试未成功”关闭。

## 4. 反例驱动的候选搜索

一个研究回合可以采用下面的 CEGIS 流程：

1. 固定声明域、模板语法、参数范围及语义版本。
2. 根据已有约束生成候选模板。
3. 攻击者优先检查边界、退化情况和历史困难实例。
4. 若找到反例，独立检查它确实在声明域内且击穿当前候选。
5. 把已检查的反例加入约束集合，再生成下一个候选。
6. 若有限攻击没有击穿候选，将状态标为“尚未被这些测试反驳”。
7. 只有对整个声明域完成证明后，才把候选注册为覆盖规则。

精确计算公式时，应保留有理数与整除条件。截断或四舍五入会改变模板本身，不能默默替换原表达式。

## 5. 证明图与覆盖账本

每个节点至少保存：

```text
statement_id
definition_version
quantifiers
domain
hypotheses
dependencies
status
certificate
verified_counterexamples
```

建议区分：开放、有限测试存活、已反驳、条件成立、人工数学复核通过、形式化检查通过。它们不是同一种可信度。

子分支排除合并为父分支排除时，必须检查子域覆盖父域。缩小声明域可以产生一条有效的新规则，但未覆盖的区域仍需保留在账本里。

证明依赖图不得出现循环。某个引理引用了与主猜想同样强的未经证明前提，应保留为条件结果，不能计为主目标完成。

## 6. 证书检查器的实现边界

- 接收严格结构化输入，检查整数类型、版本与作用域。
- 重新计算搜索范围，不信任输入提供的范围。
- 检查覆盖的具体元素，不能只检查记录数量。
- 发现无效证书时返回拒绝或错误，不能把错误转换成“无解”。
- 预算中止返回 `UNKNOWN`，并保留尚未检查的区域。
- 原子算术检查与独立参考枚举适合测试实现，但有限测试不是一般正确性的证明。

若扩展区间剪枝，对 $y\in[L,U]$ 必须证明整个区间都不可能有解。例如固定 $a,b$ 后，$aU\le b$ 可排除全部正第三分母；$aL>2b$ 可排除全部满足 $z\ge y$ 的候选。一个点的非整除事实不能扩展为相邻点也失败。

## 7. 后续实现的里程碑

1. 在固定环境中复现整数检查、证书篡改测试及两种枚举的交叉检查。
2. 形式化排序、完整边界和整除等价这几个基础引理。
3. 为候选模板建立小型纯表达式语法与精确解释器。
4. 加入模板反例证书和同余覆盖账本。
5. 接入 LLM 作为不受信任的候选提出者，保持检查器接口独立。
6. 最后再加入任务队列、预算控制、持久化和长期运行监控。

一个局部新恒等式或一个严格失败证书都可以成为研究产出。只有主目标的所有范围和所有证明义务都被关闭，才可能声称解决总猜想。
